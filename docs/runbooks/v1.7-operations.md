# WorldPulse V1.7 运维手册

## 启动与就绪门禁

推荐 PostgreSQL 团队部署：

```powershell
$env:WORLDPULSE_AUTH_MODE = "local"
$env:WORLDPULSE_REQUIRE_WORKERS = "1"
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up -d --build
curl http://127.0.0.1:8010/api/ready
```

默认 `WORLDPULSE_REQUIRE_WORKERS=0` 适合开发：API/数据库/Rule Pack 正常但 worker 未启动时返回 `degraded` + HTTP 200。生产设为 `1` 后，两类 worker 任一缺失或租约过期都会返回 503。

## Worker 排空

通过中文运维中心或管理员 API 请求 drain。worker 会完成当前任务，在下一次领取前写入 `stopped` 并退出。进程收到 SIGTERM/SIGINT 使用同一边界。不要使用强制终止，除非进程已失去心跳；生命周期任务仍可由既有 stale-job 恢复逻辑接管。

```powershell
curl -X POST http://127.0.0.1:8010/api/v6/workers/<worker-id>/drain `
  -H "X-CSRF-Token: <token>" --cookie "worldpulse_session=<session>; worldpulse_csrf=<token>"
```

## 配额响应

429 表示创建请求会越过组织硬限制。先检查 `/api/v6/organizations/{id}/operations`：

1. 确认当前用量和滚动 24 小时采集计数。
2. 识别异常积压或失去心跳的 worker。
3. 若为计划容量增长，由管理员提高配额；系统追加 previous/current 审计事件。
4. 不删除已完成 run、Evidence Snapshot 或 Replay Pack 来“修复”配额。

Idempotency-Key 重放原请求不会重复计数。若同一 key 对应不同内容，仍返回 409。

## 故障判读

- `database:*`：数据库连接或迁移验证失败，先停止写流量并运行 `python -m app.manage migrate verify`。
- `no_active_rule_pack`：规则基线不存在或损坏，禁止运行；按可信度中心流程恢复 active Rule Pack。
- `required_workers_unavailable`：生产容量门禁失败；检查容器、心跳租约和 drain 状态。
- `stale` worker：记录保留用于审计；启动替代进程后，新进程会注册新的 worker ID。
