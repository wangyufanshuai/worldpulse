# WorldPulse V1.12 官方历史基准整理手册

V1.12 的数据发布分为三个不可跳过的工作波次：

1. `pilot`：六个领域各 2 例，共 12 例，仅写入
   `benchmarks/historical-benchmark.v1/work/`，不进入数据库。
2. `wave`：六个领域数量相等的扩展批次，仍只写入 work 目录。
3. `release`：六个领域各 20 例，按 cutoff 和 case ID 排序后每领域第
   4、8、12、16、20 例为 blind，形成 90 development + 30 blind。

每项 Evidence 还必须包含 `rights_review`：决定为 `approved`，范围固定为
`local_archive_and_evaluation`，并记录复核人、复核时间和许可依据。校验器把
Publisher、材料 URL、许可名称、许可 URL 和复核内容一起计算 `review_hash`；
后续修改任一字段都会 fail-closed。许可证政策明确并不表示其中每份报告都能
归档，复核人仍须检查材料自己的许可声明与第三方内容例外。

## 受限 CLI

```text
python -m app.manage benchmark prepare-pilot \
  --file benchmarks/historical-benchmark.v1/work/pilot-curation-dossier.json \
  --output benchmarks/historical-benchmark.v1/work/pilot-curation-dossier.json

python -m app.manage benchmark validate-pilot-dossier \
  --file benchmarks/historical-benchmark.v1/work/pilot-curation-dossier.json \
  --output benchmarks/historical-benchmark.v1/work/pilot-curation-dossier.json

python -m app.manage benchmark finalize-pilot \
  --file benchmarks/historical-benchmark.v1/work/pilot-curation-dossier.json \
  --reviewer benchmark-reviewer \
  --output benchmarks/historical-benchmark.v1/work/source-plan.pilot.json

python -m app.manage benchmark validate-source-plan --file source-plan.json --profile pilot
python -m app.manage benchmark fetch-sources --file source-plan.json --profile pilot
python -m app.manage benchmark source-status --file acquisition-lock.json
python -m app.manage benchmark build-manifest --file acquisition-lock.json --source-plan source-plan.json --profile pilot --output benchmarks/historical-benchmark.v1/work/manifest.pilot.json
python -m app.manage benchmark preflight --file manifest.json --profile pilot
```

`prepare-pilot` 只规范化候选并计算 Dossier Hash，不生成批准结论。
人工复核人必须逐项填写 24 个 `rights_decision`、12 个 `label_review` 和
人工假设理由，并把状态改为 `review_ready`。随后运行
`validate-pilot-dossier` 重新固定 Hash。`finalize-pilot` 使用交互式密码提示，
只接受启用中的本地 `benchmark-reviewer`/`reviewer` 账户；密码不会进入命令行、
文件或日志。最终 Source Plan 将绑定 reviewer user ID、角色、复核时间和
Dossier Hash。

Pilot 的 `label_confidence` 在草稿中必须保持 `null`，由人工标签复核时填写。
任何 `rights_decision` 或 `label_review` 仍为空时，禁止下载材料或生成 Source
Plan。

只有 `release` Manifest 可以执行 `ingest-manifest`。partial Manifest 不得创建
Benchmark Suite、Label Pack、Evaluation Batch 或 Run。

材料只允许来自人工审核的公开 HTTPS URL。下载器会复用 SSRF、DNS 重绑定、
重定向、MIME、大小、UTF-8、PDF/JSON 签名、未来时间和内容 Hash 门禁。原文
写入 `data/benchmarks/sha256/{prefix}/{sha256}`，Git 只保存来源计划、锁文件、
Manifest Hash、定位和许可证审核记录。

## 标签与三身份

development 标签进入正式 Manifest；blind 标签只在离线明文工作区存在，使用
AES-256-GCM 加密和 Ed25519 签名后导入。三个本地身份必须相互独立：

- `benchmark-importer`：admin，只能导入；
- `benchmark-reviewer`：reviewer，第一次审批；
- `release-admin`：admin，第二次审批和发布运行。

提交者不能审批自己的标签包。标签比较开始后状态为 `consuming`，正式报告生成
后变为 `consumed`，不能重复用于下一次正式发布。

许可证不允许归档、来源 Hash 不一致、Evidence 覆盖不足或三身份审批缺失时，
保持 fail-closed，不创建 `v1.12.0-rc1`。
