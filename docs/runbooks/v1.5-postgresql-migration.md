# WorldPulse V1.5 PostgreSQL 迁移手册

> V1.6 已提供真实 PostgreSQL 并发门禁和内置数据转移命令；新部署请使用 [`v1.6-postgresql-production.md`](v1.6-postgresql-production.md)。本页保留为 V1.5 历史基线。

SQLite 仍是 V1.5 默认和完全支持的后端。首次 PostgreSQL 切换应先在 staging 复制验证，不要直接把生产 SQLite 文件“原地转换”。

## 1. 预检与备份

```powershell
python -m pytest -q
python -m app.manage migrate verify
python -m app.manage db-readiness --output docs/db/postgresql-v15-schema.sql
python scripts/backup_database.py --source data/worldpulse.db --output data/backups/worldpulse-pre-pg.db
```

`db-readiness` 必须返回 `status=ready`、`blocker_count=0` 和四个 migration。导出的 SQL 仅用于审阅和灾备；正式建表仍由编号迁移执行。

## 2. 建立空数据库

安装 `requirements.txt` 中的 `psycopg[binary]`，创建专用数据库和最小权限用户。然后在维护窗口设置：

```powershell
$env:WORLDPULSE_DATABASE_URL="postgresql://worldpulse:<password>@127.0.0.1:5432/worldpulse"
$env:WORLDPULSE_AUTO_MIGRATE="1"
python -m app.manage migrate
python -m app.manage migrate verify
```

迁移完成后将 `WORLDPULSE_AUTO_MIGRATE=0`。生产启动只验证 checksum 和 migration 状态，不静默改 schema。

## 3. 数据搬迁

V1.5 提供 schema/runtime portability，但不内置生产数据复制器。数据搬迁必须使用一次性、可审计脚本或 ETL，并遵守外键顺序：users/projects → runs/graphs/reports → lifecycle/trust/evidence → organizations/ingestion。每张表核对 row count；对 Rule Pack、artifact、Evidence Snapshot/Pack、ingestion manifest 重算 Hash。

任何 Hash、外键或 count 不一致都停止切换，不允许“跳过坏记录”上线。

## 4. Smoke gate

在 staging 启动 API、run worker 和 ingestion worker，验证：

```text
GET /api/health
GET /api/version
python -m app.manage migrate verify
```

随后执行登录、组织项目创建、确定性 War Room、Run Diff、Replay Pack、Evidence Pack、手工接入和 worker `--once`。至少完成一次备份恢复演练。

## 5. 切换与回滚

停止所有写入和两个 worker，做最后 SQLite 备份与增量复制，完成 Hash/count 校验后再切换连接串。回滚时停止 PostgreSQL 写入，恢复原 SQLite 备份，清除 `WORLDPULSE_DATABASE_URL`，重新执行 SQLite `migrate verify` 后启动；不要把切换后的两端同时作为可写主库。

本地工作区若没有运行中的 PostgreSQL 服务，只能完成迁移翻译、查询适配和 schema 合同测试；这不能替代 staging 的真实 PostgreSQL smoke test。
