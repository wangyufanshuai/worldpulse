# WorldPulse V1.3 Operations Runbook

## Initial deployment

1. Back up the SQLite file and stop API/worker processes.
2. Run `python -m app.manage migrate` and then `python -m app.manage migrate verify`.
3. Create the first administrator with `python -m app.manage create-admin --username <name>`; enter the password at the prompt.
4. Set `WORLDPULSE_ENV=production`, `WORLDPULSE_AUTH_MODE=local`, `WORLDPULSE_AUTO_MIGRATE=0`, and an explicit HTTPS origin in `WORLDPULSE_CORS_ORIGINS`.
5. Start the API and the independent `python -m app.workers.run_worker` process.
6. Confirm `/api/health`, `/api/version`, login, Trust Center, and `/api/v2/lifecycle/health`.

Create additional least-privilege accounts with `python -m app.manage create-user --username <name> --role analyst|reviewer|viewer`; enter passwords interactively.

Production startup checks schema only. It never silently applies a migration. The migration command writes a temporary sibling backup and restores it if any numbered migration fails.

## Role procedures

### Administrator

- Manages local users out of band and activates reviewer-approved Rule Packs.
- Cannot activate a pack whose calibration artifact/hash or gate result fails.
- Reviews auth failures, 401/403 counts, pending critical reviews, and database backups.

### Analyst

- Creates projects and runs, starts calibration, generates reports, Run Diff, and Replay Pack.
- May submit a Rule Pack draft but cannot approve it.
- Must treat the 30-case bundled corpus as regression evidence, not external historical truth.

### Reviewer

- Examines Rule Pack manifests, calibration metrics, artifact hashes, evidence coverage, and Review Cases.
- Can approve a pack created by someone else only after all gates pass.
- Cannot manually admit a rejected/constrained/expired Agent action.

### Viewer

- Reads projects, reports, Replay Pack, Run Diff, lifecycle audit, and Trust Center.
- Cannot create or mutate projects, runs, rules, calibration, or reviews.

## Rule Pack promotion

1. Analyst creates and submits a draft.
2. Analyst runs the complete 30-case calibration lifecycle.
3. Reviewer verifies metrics and the `calibration_metrics` SHA-256 artifact.
4. Reviewer approves; the pack becomes `candidate`.
5. Administrator activates it; the old active pack becomes `retired`.
6. Create a new War Room run and verify the new Rule Pack ID/Hash. Existing runs and retries retain their pinned hash.

## Incident response

- Artifact mismatch: stop promotion, keep fail-closed, preserve the DB, create a backup, and inspect the critical Review Case.
- Repeated auth failures: inspect `security_audit_events`, rotate the affected password, revoke sessions, and verify CORS/proxy configuration.
- Migration failure: keep services stopped; confirm the `.pre-migrate.bak` restoration and run `migrate status` before retrying.
- Worker crash: restart the worker. Lifecycle attempts, leases, steps, and artifacts preserve recovery state.
- Calibration failure: do not edit results or labels. Create a new Rule Pack draft or a new versioned case and rerun.

## Release gates

Run the commands in the root repository:

```text
python -m pytest -q
npm --prefix frontend run test:unit
npm --prefix frontend run build
npm --prefix frontend run test:e2e
python -m compileall -q app
python -m app.manage migrate verify
python scripts/export_openapi.py
python scripts/verify_release_artifacts.py
git diff --check
```
