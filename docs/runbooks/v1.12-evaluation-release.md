# V1.12 评估发布运行手册

1. Complete and review the `pilot` and `wave` curation work; only the final
   `release` profile may proceed.
2. Start the isolated PostgreSQL Compose project and migrate it.
3. Place licensed official material under `data/benchmarks/sha256/{prefix}/{sha256}`.
4. Run `benchmark source-status`, `benchmark preflight --profile release`, then
   `benchmark ingest-manifest --file <manifest.json>`.
5. Import and obtain two-person approval for a sealed blind label pack.
6. Run `python -m app.manage benchmark verify`.
7. Run `python -m app.manage evaluation run-release --provider mock --label-pack <id> --wait`.
8. Run `python -m app.manage evaluation verify` and inspect every failed verification and critical Review Case.
9. Create the release checkpoint and `v1.12.0-rc1` tag only after exactly
   84 Engineering + 330 Historical members and all fail-closed gates pass.

Never expose the blind decryption key to the API image used for ordinary operation. It is only supplied to the isolated release evaluator.

## Manual `evaluation_full` workflow

The repository's `.github/workflows/evaluation_full.yml` is deliberately a
manual gate. It must run on a dedicated self-hosted runner labelled
`worldpulse-release-evaluation`; a normal hosted runner has no approved corpus
or sealed labels and therefore fails closed. Configure the `release-evaluation`
environment with:

- `WORLDPULSE_EVALUATION_DB_PATH`: a disposable database already containing
  the active release suite and the two-person-approved sealed label pack;
- `WORLDPULSE_BENCHMARK_ROOT`: the content-addressed benchmark blob directory;
- secret `WORLDPULSE_BLIND_LABEL_KEYS`: the JSON key map required to decrypt the
  selected sealed pack.

Before dispatch, verify the material with the commands above. Then dispatch
the workflow with the exact existing `label_pack_id` (for example, the value
returned by `benchmark status`). The workflow checks for all 120 corpus cases,
the active 30-case pack, its matching decryption key and the external paths
before invoking the existing `evaluation run-release --provider mock --wait`
contract. Missing material is an error; it is never converted into a pytest
skip or a passing result. The input is an identifier only: CI does not create,
download, or fabricate benchmark data.
