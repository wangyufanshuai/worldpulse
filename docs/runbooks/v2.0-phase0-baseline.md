# V2.0 Phase 0 baseline runbook

This runbook records the engineering baseline before the first V2 module
migration. It is not a V1.12 release approval and it does not approve the
historical Pilot corpus.

## Baseline scope

- Git baseline: `8e4b20d`
- Application version: `1.12.0-dev`
- API contract: `v11`
- Historical Pilot: 24 Evidence reviews pending, 12 Case reviews pending
- V1.12 release track: frozen and separate from V2 code work

## Required local checks

```powershell
python -m compileall -q app
python scripts/verify_v2_boundaries.py
python -m pytest -q
npm --prefix frontend run test:unit
npm --prefix frontend run build
npm --prefix frontend run test:e2e
python -m app.manage migrate verify
python scripts/verify_release_artifacts.py
npm --registry=https://registry.npmjs.org --prefix frontend audit --audit-level=high
git diff --check
```

The backend and browser checks are intentionally separate: a green SQLite
run does not prove PostgreSQL concurrency, and a green unit suite does not
prove browser lifecycle cleanup.

## Phase 0 exit criteria

1. `v2.0-architecture-program.md`, ADR-0001 and the boundary manifest are
   present and reviewed by the implementation agent.
2. `verify_v2_boundaries.py` passes with zero forbidden imports.
3. Frontend lockfile and high-severity npm audit pass.
4. `requirements.lock` installs and passes the full suite in an isolated
   CPython 3.11 environment; the global developer environment is not accepted
   as the reproducibility proof.
5. The full non-live regression suite remains green.
6. A local, reversible checkpoint exists; no remote push or release Tag is
   created.
