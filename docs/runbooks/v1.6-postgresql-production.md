# WorldPulse V1.6 PostgreSQL production runbook

V1.6 keeps SQLite as the zero-configuration development default and makes PostgreSQL the recommended shared-team backend. The v1-v5 HTTP contracts and deterministic War Room results are unchanged.

## Start the PostgreSQL stack

Use an explicit password outside local development. Production must also use local authentication and an explicit CORS allowlist.

```powershell
$env:WORLDPULSE_POSTGRES_PASSWORD = "replace-with-a-secret"
$env:WORLDPULSE_AUTH_MODE = "local"
$env:WORLDPULSE_CORS_ORIGINS = "https://worldpulse.internal"
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up -d --build
```

The overlay starts PostgreSQL 16, the API, the deterministic lifecycle worker, and the ingestion worker. PostgreSQL health must pass before the API starts; workers wait for API health.

For controlled production rollout, set `WORLDPULSE_AUTO_MIGRATE=0` and run migrations as a separate deployment step:

```powershell
$env:WORLDPULSE_DATABASE_URL = "postgresql://worldpulse:...@127.0.0.1:5432/worldpulse"
python -m app.manage migrate
python -m app.manage verify
```

## Transfer an existing SQLite database

Back up the SQLite file and copy into a fresh PostgreSQL database:

```powershell
python scripts/backup_database.py --source data/worldpulse.db --output data/backups/worldpulse.pre-v16.db
python -m app.manage db-copy --source data/worldpulse.db --target-url $env:WORLDPULSE_DATABASE_URL
```

The command applies canonical migrations, inserts all 36 business tables in foreign-key-safe order, and verifies every table using row count plus an order-independent SHA-256 digest. It never prints the target URL. Any copy or verification failure rolls back the transfer transaction and exits non-zero.

Re-run verification without writing:

```powershell
python -m app.manage db-copy --source data/worldpulse.db --target-url $env:WORLDPULSE_DATABASE_URL --verify-only
```

## Required release gates

```powershell
python -m app.manage migrate verify
python -m pytest -q tests/test_postgres_integration_v16.py
python -m app.manage db-copy --source data/worldpulse.db --target-url $env:WORLDPULSE_DATABASE_URL --verify-only
```

The live PostgreSQL test covers concurrent `SKIP LOCKED` worker claims, atomic monotonic events, deterministic lifecycle completion, and projection back to the existing workspace and Replay Pack.

## Rollback

Keep the source SQLite backup read-only until the PostgreSQL verification and application smoke tests pass. Rollback switches `WORLDPULSE_DATABASE_URL` off and restores the SQLite configuration; completed runs and Replay Packs remain bound to their stored Rule Pack and artifacts. Never merge two independently written databases during rollback.
