# WorldPulse V1.10：持续情报监测与告警闭环

V1.10 在 V1.9 受治理材料链路前增加一个默认关闭的持续情报入口，同时保持确定性数值权威边界：

```text
RSS / Atom / JSON Feed
  -> 安全轮询、ETag/Last-Modified 与 revision 去重
  -> 不可变 Watchlist 的确定性规范值匹配
  -> 内容寻址 Markdown 材料
  -> V1.9 确定性抽取、Evidence Snapshot 与待核验 Candidate
  -> Analyst 决策、Draft、异人审批与运行
```

## 信任边界

Feed、XML、JSON 和 Webhook 目标全部视为不可信外部输入。后台监测不得调用 LLM，不得自动接受 Candidate、创建 Draft 或启动 Run，也不得生成风险、供应链压力、国家或链路 override。命中规则只允许使用现有 `scenario_preset`、`country`、`supply_chain` 和 `policy_action` 规范值。

外部访问由 `WORLDPULSE_CONTINUOUS_INTELLIGENCE=1` 显式启用。生产环境只接受 HTTPS；URL、每次重定向和最终解析地址均执行 SSRF 检查，拒绝本机、私网、链路本地、保留地址、用户凭据和非允许端口。客户端不使用环境代理、Cookie 或页面脚本，并限制响应大小、条目数和规范化文本长度。

## 持久化与幂等

迁移 `0008_v110_continuous_intelligence` 增加 Source、Poll Job/Event、Entry Revision、Watchlist/Rule、Alert/Event、Subscription、Notification 与 Webhook Delivery。Source 和已激活 Watchlist 不原地修改；配置变化通过 clone 形成新版本。

稳定条目 ID 与内容 Hash 共同控制 revision。相同内容不会重复产生 Alert、Document、Extraction、Candidate 或 Notification；内容改变会追加 revision 并重新打开原告警线程。命中内容确定性渲染为 Markdown，随后复用 V1.9 Blob Store 和 extraction worker。Alert lineage 固定 Source、Watchlist、Entry、Document、Extraction、Snapshot 与 Candidate 标识及 Hash。

## 调度、恢复与通知

不新增进程类型。现有 ingestion worker 创建到期 Poll Job，并在手工采集、文档抽取、Feed Poll 和 Webhook Delivery 间按最早到期时间领取。租约支持崩溃恢复；失败执行有界退避，连续失败会将 Source 标记为 `degraded`。

站内通知使用组织级单调序列和 SSE 断点续传。Webhook 只发送 ID、Hash、严重度、匹配规则、时间和应用深链，使用 HMAC-SHA256 签名；明文 secret 只从 `WORLDPULSE_WEBHOOK_SECRET_{REF}` 环境变量解析，不进入数据库或日志。

## 兼容性

V9 API 只增加组织/项目作用域的持续情报资源；v1-v8 URL、字段含义、生命周期、Run Diff、Replay Pack、Rule Pack、Agent Pack 和确定性结果保持不变。
