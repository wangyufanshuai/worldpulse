# WorldPulse V1.9：证据驱动场景编译

V1.9 closes the governed input loop without changing the authority boundary of the deterministic engine:

```text
PDF / TXT / Markdown / CSV
  -> content-addressed blob + metadata gates
  -> versioned extraction + evidence snapshots
  -> deterministic candidates with page/line/row locators
  -> analyst append-only decisions
  -> immutable Scenario Draft + frozen Evidence Pack
  -> independent Reviewer/Admin approval
  -> deterministic / hybrid / negotiation run
```

## Authority and trust boundaries

Uploaded bytes are untrusted data. They cannot override prompts, Action Contracts, Rule Packs, risk values, supply-chain pressure, or country/chain overrides. The deterministic compiler emits only `scenario_key`, target countries, target chains and policy actions. Duration, intensity and propagation are explicit human assumptions with default/selected values and a reason.

The optional extraction provider is disabled by default. When explicitly enabled, it may add only fixed candidate types and must provide an exact source excerpt. Unknown entities, missing locators and numeric/override fields are stored as invalid or cause a strict failure. Only provider/model/prompt/response hashes, token estimates, latency and fallback state are retained.

## Persistence and recovery

Migration `0007_v19_scenario_compiler` adds source documents, extraction jobs/events, extractions, candidates, decisions, drafts/items and draft reviews. Raw bytes live outside SQLite/PostgreSQL under `data/uploads/sha256/{prefix}/{hash}`. The existing ingestion worker fairly claims manual ingestion and extraction queues. Completion writes snapshots, candidate hashes, extraction manifest and document status; retry creates a new job with parent lineage.

Submission computes a Draft hash over the compiler version, scenario, assumptions, candidate hashes, pinned decision hashes, extraction hashes and Evidence Pack hash. Later candidate decisions do not mutate a submitted Draft. Any mismatch is fail-closed. A run created from an approved Draft stores Draft ID/hash and Evidence Pack hash in `run_jobs`; downstream Trust Manifest, Replay Pack and reports retain the lineage.

## API and UI

The v8 routes are organization/project scoped and preserve v1-v7 contracts. Reviewer/Admin approval is an independent write permission; the submitter cannot approve their own Draft. The War Room compiler has six stages: upload, extraction, candidate verification, draft, dual approval and run creation. It projects existing lifecycle and worker data and does not introduce a new process type.
